# Dynamic application answers

Application material preparation now also drafts saved form fields. The application workspace displays their answers, character limits, choice labels, review state, and any missing information. Users can add questions, edit answers, and use “Find fields & draft missing answers” independently of resume generation. Edited answers are saved with the application; drafting does not overwrite existing nonempty answers or submit an external form.

MCP `prepare_application` accepts optional `fields` alongside `job_id`. `prepare_application_answers` accepts `application_id` and optional `fields`, merges definitions by stable ID, and returns drafts. Use the actual field name/id, visible label, type, required flag, exact choice labels, and `max_length` from the application form. Omit `answer` to request a draft; supply it only when the candidate has supplied the answer. Changes to a field's meaning invalidate its previous answer. The `get_application` and `get_application_materials` tools expose saved answers too.

Supported types: text, textarea, email, URL, number, date, select, multiselect, checkbox and file. Up to 60 fields are supported per application. Public HTML forms are extracted during Brave page verification. Preparation can also retrieve Greenhouse's public question schema, including custom questions, and read existing public application URLs. No login, browser automation, or submission happens server-side. Forms rendered only by JavaScript, behind login, or with conditional steps need the browser/MCP agent to provide the fields it sees. An empty discovery result is not proof that the application has no questions.

Contact fields use saved profile/account information. Motivation and other writing questions use the job posting, candidate evidence and material instructions. Unsupported facts, consent, demographics, file uploads, and selections requiring personal judgment are left for the candidate. Generated answers are explicitly drafts; review them before submission. File fields point users toward the materials rather than pretending a file has been uploaded. Exact select choices, field lengths, evidence IDs, account ownership, and concurrent field changes are checked server-side.
